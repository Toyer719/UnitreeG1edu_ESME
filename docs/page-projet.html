Avant tout

Lancer les simulations, pas à pas

g1-sim gl-sim chiffre 1, pas la lettre L

Pourquoi « commande introuvable »

Votre historique montre gl-sim-marche : vous avez tapé la lettre L minuscule. Le nom du robot s'écrit avec le chiffre 1 : g1. Sur un clavier AZERTY, le 1 s'obtient avec Maj + &, ou sur le pavé numérique. Les deux orthographes marchent désormais, mais le plus sûr reste de copier la commande ici et de la coller dans le terminal.

  1. Ouvrir un terminal

    Appuyez sur Ctrl + Alt + T. Une fenêtre s'ouvre avec une ligne qui se termine par ~$ : le terminal attend votre commande. Pour un deuxième terminal dans la même fenêtre : Ctrl + Maj + T.

  2. Copier la commande ici, la coller dans le terminal

    Cliquez sur « Copier » à côté d'une commande. Dans le terminal, collez avec Ctrl + Maj + V, ou clic droit puis Coller. Le simple Ctrl + V ne marche pas dans un terminal.

  3. Appuyer sur Entrée

    La commande démarre. Pour l'arrêter : Ctrl + C dans le terminal, ou fermer sa fenêtre.

  4. Astuce : la touche Tab

    Tapez g1- puis appuyez deux fois sur Tab : le terminal affiche toutes les commandes du projet. Tapez le début d'un nom et Tab complète le reste, sans faute de frappe possible.

Sans manette physique : la manette virtuelle

Une fenêtre qui se comporte comme une manette Xbox branchée : le simulateur la voit comme une vraie. On la pilote en maintenant les touches, comme un vrai stick.

    g1-manette-virtuelleprête

Simulation 2 · Le simulateur officiel relié au SDK

Il faut deux terminaux : le premier fait tourner le robot simulé, le second lui parle comme on parlera au vrai robot.

  1. Terminal 1 : lancer le simulateur. Le G1 pend à un élastique, comme sur le portique (touches 7 8 pour monter et descendre, 9 pour le lâcher).

    g1-simprête

  2. Terminal 2 (Ctrl + Maj + T) : lire l'état du robot simulé. Arrêter avec Ctrl + C.

    g1-etat loprête

  3. Terminal 2 : faire bouger le robot simulé, moteur par moteur. Appuyez sur Entrée quand la démo le demande.

    g1-sim-demoprête

Toutes les commandes

Chaque commande renvoie aux jours où elle sert. Celles qui commencent par ros2 utilisent ROS 2 directement ; celles qui commencent par g1- sont les raccourcis du projet, rangés dans ~/robot-g1/bin. Le guide détaillé est dans ~/robot-g1/README.md.

Comprendre le projet

Architecture, outils, risques

Ce qui est faisable, et à quel prix

Détecter les visiteurs avec une caméra en plusSimple

Caméra See3CAM fixée sur la poitrine, détection YOLO accélérée sur le Jetson, distance estimée par la taille des personnes.

Dialoguer en françaisMoyen

Chatbot à règles et reconnaissance vocale hors ligne. Le vrai obstacle est le bruit d'une journée portes ouvertes : prévoyez une tablette.

Scanner le bâtiment en 3DSimple

Le LiDAR 3D de la tête suffit. FAST-LIO2 construit le nuage de points pendant que le robot parcourt les couloirs.

Placer les salles et y accompagnerMoyen

Points nommés sur la carte, Nav2 calcule le trajet. Le plus long est de fiabiliser la localisation.

Contourner la foule, changer d'itinéraireLong à régler

Nav2 recalcule en continu, un graphe des couloirs fournit les itinéraires de secours. Rien à « entraîner » : ce sont des réglages et des tests.

Logiciel de configuration multi-lieuxMoyen

Application web : lieux, cartes, salles, phrases, modes. Tout est rangé dans un « paquet de lieu » par bâtiment.

Escaliers et plusieurs étagesHors périmètre

Trop risqué en deux mois. Le robot accompagne jusqu'à l'escalier ou l'ascenseur, puis explique la suite.

Le scénario d'accueil

  1. Attente

    Au point d'accueil, le robot surveille le hall.

  2. Accroche

    Une personne à moins de 3 m regarde le robot : coucou, « Bonjour ! ».

  3. Dialogue

    À moins de 1,5 m : écoute, comprend la salle, demande confirmation.

  4. Guidage

    « Suivez-moi. » Navigation vers la salle, quelques phrases en route.

  5. Arrivée

    Phrase d'arrivée propre à la salle, geste d'au revoir.

  6. Retour

    Revient au point d'accueil, puis repasse en attente.

BloquéDemande le passage au bout de 3 s, change de couloir au bout de 8 s.
Batterie faiblePrévient le visiteur et rentre sous 25 %.
ArrêtTélécommande ou bouton du logiciel, priorité absolue.

Le paquet de lieu

Le logiciel de configuration lit et écrit ces fichiers. Changer de bâtiment revient à charger un autre paquet : le code ne change jamais. Pour le mode « méchant », visez le sarcasme bienveillant et faites valider les phrases par l'établissement.

Ce qui peut mal tourner, et la parade

RisqueParade
Le bruit empêche la reconnaissance vocale

Tablette kiosque, micro directionnel, questions fermées (« oui » ou « non »).

Le LiDAR ne voit pas les vitres

Zones interdites sur la carte ; la caméra de tête complète.

Le robot se perd dans un long couloir uniforme

AMCL bien réglé, départ toujours du point d'accueil, recalage depuis le logiciel.

Le Jetson sature (carte, Nav2, YOLO, voix)

Modèles « nano » en TensorRT ; reconnaissance vocale déportée sur un portable en Wi-Fi si besoin.

La batterie tient environ 2 h

Retour automatique sous 25 %, batterie de rechange, planning de charge.

Une mise à jour Unitree change le SDK

Versions figées dans ~/robot-g1/third_party/VERSIONS.txt.

Un visiteur est heurté

0,6 m/s maximum, arrêt sous 0,4 m, un accompagnateur avec la télécommande pendant tout l'événement.

Le visiteur ne suit plus

Le robot se retourne aux carrefours et l'attend ; caméra arrière en option.
